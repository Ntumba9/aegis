# Changelog

All notable changes to AEGIS are documented here. Format loosely follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased] — Milestone 4

### Changed
- `backend/requirements.txt`: `httpx` pinned to 0.27.2 (was 0.28.1).
  `supabase==2.10.0` requires `httpx<0.28`, so the old pin made
  `pip install -r backend/requirements.txt` fail with `ResolutionImpossible`
  — the cause of the backend failures in the first CI run (2026-10-27).
  `lab/requirements.txt` keeps 0.28.1 (the lab does not depend on supabase).

### Added (fifth pass)
- Docker Compose now publishes the platform backend (8000) and frontend
  (3000) on `127.0.0.1` by default (previously all interfaces);
  `BACKEND_BIND_ADDR` / `FRONTEND_BIND_ADDR` in `.env` change it. The lab's
  ports are unchanged.

### Added (fourth pass)
- `backend/openapi.json`: the live OpenAPI 3.1 schema, generated by
  `backend/scripts/export_openapi.py` and committed to the repo —
  satisfies the "API documentation" deliverable with the actual schema
  rather than hand-written docs that drift. CI now fails if it's stale.

### Added (third pass)
- **`PATCH`/`DELETE` for tasks, `PATCH` for projects.** Previously
  create-and-list only — there was no way to ever mark a task done, or
  rename a project. Added to `backend/app/api/projects.py`, wired to a
  "mark done" control in the frontend org dashboard.
- **Schemathesis fuzz testing** (`backend/tests/integration/test_api_fuzzing.py`):
  `schemathesis` had been sitting in `requirements.txt` since Milestone 1,
  listed in the original tech stack as the "API security regression
  tests" tool, and was never actually used anywhere. It now generates
  property-based requests from the app's own OpenAPI schema (58 cases
  across all 62 routes) and asserts none of them produce an unhandled
  500 — a 401/403/422 is a correct response and not a failure.
- 5 new integration tests for the project/task endpoints — 97 backend
  tests total, up from 39.

### Added (second pass)
- **Documents API** (`backend/app/api/documents.py`, `app/services/storage.py`):
  upload/list/download/delete backed by Supabase Storage, with a 25MB
  upload cap. There was previously a `documents` table and no API at all.
- **Webhooks API** (`backend/app/api/webhooks.py`): registration, listing,
  deactivation, and a "send test event" action using the existing signing
  service. There was previously a `webhooks` table and a signing/delivery
  service with zero REST endpoints wired to it.
- A real frontend for the core SaaS app: `/orgs` (list/create),
  `/orgs/[id]` (tabbed dashboard — projects/tasks, documents, API keys,
  webhooks), on top of the existing `/orgs/[id]/security`. Previously the
  entire main SaaS app had backend endpoints and zero frontend.
- Password reset flow (`/login`'s "Forgot password?" + `/reset-password`)
  — explicitly required by the spec and previously missing entirely.
- 6 new integration tests (documents, webhooks) — 34 backend tests
  total, up from 28.

### Fixed
- **`security_events` table didn't exist.** `app/core/audit.py::record_event()`
  wrote to a table that was never migrated, and the function was never
  called from anywhere — pure dead code pointing at a missing table.
  Added migration `0006_security_events.sql`, a request/security-event
  logging middleware (`app/middleware/security_logging.py`) that actually
  calls it on every request, and the Blue Team security-ops API
  (`GET /orgs/{org_id}/security/events`, `/metrics`) + frontend page
  (`/orgs/[id]/security`) that reads from it — closing the "Security
  events, alerts, audit logs" requirement that had no real implementation
  behind it.
- **No way to list your own organizations.** Every other collection
  endpoint (`/teams/mine`, `/classrooms/mine`) had a `mine` route;
  `/orgs` never did. Added `GET /orgs/mine` and a minimal `/orgs`
  frontend page.

### Added
- Vulnerability report Markdown export (`GET /teams/reports/{id}/export`)
  for the Red Team dashboard's report-export requirement.
- 6 new integration tests covering the above (security events +
  metrics + authorization, report export, `/orgs/mine`) — 28 backend
  tests total, up from 22.
- Integration test suite (`backend/tests/integration/`) running the real
  `supabase/migrations/*.sql` against a throwaway Postgres, connecting as
  the `authenticated` role with `request.jwt.claim.sub` set per test user
  — the same mechanism PostgREST uses — to actually exercise RLS:
  - Cross-tenant isolation at the RLS layer (`test_rls_tenant_isolation.py`)
  - Achievement writes are server-only, never client-writable (`test_achievements.py`)
  - Full API-layer coverage for teams, leaderboard, and classrooms
    (`test_teams_api.py`, `test_leaderboard_api.py`, `test_classrooms_api.py`)
- `backend-integration-tests` CI job with a `postgres:16-alpine` service
  container.
- `docs/THREAT_MODEL.md` — the platform/lab trust-boundary breakdown.
- `docs/DEPLOYMENT.md` — production deployment guide and checklist.
- `CORS_ALLOWED_ORIGINS` environment variable.

### Fixed
- CORS origin was hardcoded to `http://localhost:3000` in
  `backend/app/main.py`; now configurable via `CORS_ALLOWED_ORIGINS`
  (defaults to the same value, so local dev is unaffected).
- `backend/app/main.py` used the deprecated `@app.on_event("shutdown")`
  hook; replaced with a `lifespan` context manager.

## Milestone 3

### Added
- Red Team / Blue Team collaboration: teams, team membership, attack/defense
  team sessions, vulnerability reports, remediation assignment, retesting
  (`backend/app/api/teams.py`).
- Leaderboards (individual + team), summing only `points_awarded` from
  `server_verified` completions (`backend/app/api/leaderboard.py`).
- Achievements: `first-blood`, `api-top-10-graduate`, `red-team-rookie`,
  auto-awarded server-side only (`backend/app/services/achievements.py`).
- Instructor classrooms: creation, student invites, challenge assignment,
  completion reporting (`backend/app/api/classrooms.py`).
- Frontend pages: `/teams`, `/teams/[id]`, `/leaderboard`, `/dashboard`
  (progress + achievements), `/instructor`.

## Milestone 2

### Added
- The remaining 8 OWASP API Security Top 10 (2023) categories, each as a
  vulnerable/hardened endpoint pair with a regression test:
  API2 (predictable session tokens), API3 (mass-assignment role
  escalation), API4 (unbounded pagination), API5 (missing function-level
  auth check), API6 (coupon-replay business logic abuse), API8 (verbose
  error disclosure), API9 (unprotected legacy endpoint), API10 (unsafe
  third-party response trust).

## Milestone 1

### Added
- AEGIS Platform skeleton: Next.js frontend, FastAPI backend, Supabase
  Postgres schema + RLS for the core SaaS app (orgs, projects, tasks,
  documents, API keys, webhooks, request logs).
- AEGIS Labs skeleton: isolated Docker network (`lab-net`, `internal: true`),
  the first two OWASP challenges (API1 BOLA, API7 SSRF) with vulnerable +
  hardened implementations.
- Server-side challenge verification (`backend/app/challenges/`,
  `backend/app/api/challenges.py`): completion is never decided by a
  client-submitted boolean.
- Challenge catalog, progress tracking, reset.
